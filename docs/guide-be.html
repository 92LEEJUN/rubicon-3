01내 책임 / 경계

✅ 내가 한다

  • 오케스트레이터(의도분류·흐름·tool 조합·스트리밍)

  • WebSocket 중계·인증 게이트(API/표현 계층)

03내가 빌드할 계약

  • Port 인터페이스(data-model §6) — Device·CSKnowledge·Catalog·Order·Store·Quote·Handoff·Warranty·Auth·Trust·ActionGate·Alert·Consent·Analytics + TokenProvider
  • Repository(§5) — Conversation·Session·Order·Engagement(내부 데이터)
  • 도메인 서비스 — 오케스트레이터가 인프로세스 함수로 호출, tool로 노출
  • Mock + Real 두 구현, 의존성 주입 교체. 모듈 레이아웃 data-model §8.
계약 테스트로 Mock/실이 같은 계약 만족 보장 → 교체 안전. fixtures를 Mock이 반환.

05주의 / 알아둘 결정

  • 내부=Repository / 외부=Port — "전부 API가 아니다". 오케스트레이터→도메인은 함수 호출.
  • 외부 데이터 3종 성격 — SmartThings=실시간 이벤트(구독·서명검증) / CS=정적 배치 인제스천 / 제품=demand-driven(by-id·매칭, 브라우즈 없음).
  • TokenProvider — PAT(스파이크)→OAuth(MVP)→Enterprise(조직). 데이터/이벤트 스키마는 공통, 토큰만 교체.
  • 검증 스파이크(design §7) — O2O·SmartThings 오류코드 노출·CS 매핑·부품 매핑·동의. ⚠️ ST 오류코드 API 노출 불확실.
  • 되돌릴 수 없는 커밋은 LLM 경로 밖 + ActionGate(R17).
