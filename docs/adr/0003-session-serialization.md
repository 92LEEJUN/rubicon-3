# ADR-0003: 세션 직렬화 = FE 입력차단 + 서버 세션락

- **상태**: 채택
- **관련**: `docs/operations.md` §7

## 배경
같은 사용자의 메시지는 **순서가 보장**돼야 한다(이력·FlowState 일관성). 응답 생성 중 새 입력이 들어오면 동시/추월 처리가 생긴다.

## 후보안
| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A (선택)** | **FE 입력차단**(응답 생성 중 입력/전송 비활성) + **서버 세션락**(세션 큐) | 동시/추월이 애초에 안 생김, 우회(다중 탭·재연결)도 락으로 방어, 단순·예측가능 | 한 세션은 동시 1 turn |
| B | **supersede**(새 메시지가 진행 중 turn 취소·최신 우선) | 반응성↑ | 복잡·중간상태 처리·취소 비용, 순서 의미 모호 |
| C | 서버 큐만(FE 차단 없음) | FE 단순 | 사용자가 중복 전송 → 큐 적체·혼란 |

## 결정
**A.** 1차는 FE 차단(현 `ChatPanel`이 `streaming` 동안 입력 비활성과 동일), 서버는 세션 키 단위 직렬화(세션락/큐)로 우회 입력까지 순서 보장. 세션 간은 병렬.

## 기각 이유
- B: supersede는 불필요한 복잡도. 차단이 더 단순·예측가능하고 같은 세션 추월이 없어진다.
- C: FE 차단 없으면 중복 전송으로 적체.

## 결과/영향
SLA(ADR-0005)에서 "같은 세션 supersede 불필요"의 근거. Phase B에선 `lock:turn:{sid}`(SET NX PX)로 구현(ADR-0006).
