# ADR-0025: 응답 표현 = 구조화 Template(kind+data) (vs 자유 텍스트)

- **상태**: 채택
- **관련**: `docs/response-templates.md` §1·§7, `docs/architecture.md` §1(원칙 5)

## 배경
멀티모달(R10)·템플릿/CTA(R11) 응답을 어떻게 표현할지. UI와 응답 생성을 디커플링해야 한다.

## 후보안
| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A | **자유 텍스트** 응답 | 단순·유연 | UI 구조화 불가, CTA·미디어·렌더 일관성 어려움 |
| **B (선택)** | **구조화 `Template` 모델**(kind + data 스키마) | UI 디커플링, CTA·미디어 일관, FE 레지스트리 렌더 | 스키마 관리 |
| C | 하이브리드(텍스트+부분 구조) | 절충 | 계약 모호 |

## 결정
**B.** 응답은 평문이 아니라 **Template(kind+data)** 로 전달, 렌더는 FE 담당. 14종 kind, 확장은 추가만, **모르는 kind·스키마 불일치 → `text` 폴백**.

## 기각 이유
- A: 자유 텍스트는 CTA·미디어·복합 섹션을 구조적으로 다룰 수 없다.
- C: 계약이 모호해져 FE 렌더가 불안정.

## 결과/영향
복합 응답의 섹션 구조는 ADR-0026, 카드 탭 surface 분기는 ADR-0027. FE는 kind→컴포넌트 레지스트리.
