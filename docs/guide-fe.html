📱 Frontend (React Native)

FE 필독 가이드

BE 계약(템플릿 모델)을 렌더하는 앱. 홈·CS·전역 채팅 패널·브릿지 모달. 라우팅 판단은 하지 않는다.

책임필독 문서계약다이어그램주의

01내 책임 / 경계

✅ 내가 한다

  • 화면(S1 홈·S2 CS·S3 채팅·S4 브릿지) 렌더
  • 템플릿 14종 + 섹션 스택(복합 R7) 렌더
  • 스트리밍 표시(타이핑·점진), 멀티모달 입력
  • CTA 처리(대화형→/chat, 커밋→엔드포인트)
  • 상태/훅, 분석 이벤트 발생(동의 게이트)

🚫 내가 안 한다

  • LLM이냐 도메인이냐 라우팅 판단(BE 몫)
  • 브릿지/패널 분기 결정(BE가 surface 반환)
  • 비즈니스 로직·집계(API/표현 계층)
  • 카탈로그 브라우즈 화면(없음 — 카드/챗만)

03내가 빌드할 계약 (1:1 대응)

  • templates/ ← response-templates (kind→컴포넌트 레지스트리, 모르는 kind=text 폴백)
  • transport/ ← api-contract §2.1 (ChatTransport 추상화 + WebSocket)
  • api/ ← api-contract §2.2/2.3 (결정적 엔드포인트·surface)
  • types/ ← data-model DTO (ChatRequest·MessageSection·ChatResponseChunk)
  • hooks/·state/ ← frontend-architecture §11 (useChat·useCardTap·useCta·useAnalytics + reducer)
계약 Stub로 BE 없이 개발. Stub은 fixtures(specs/.../fixtures/)를 재생 — 같은 데이터로 통합(api-contract §5).

05주의 / 알아둘 결정

  • 카드 탭 → surface: BE가 bridge(모달 S4)/panel(S3)을 동적 결정. FE는 surface만 보고 렌더.
  • CTA 두 경로: 대화형 CTA→/chat 재진입(LLM 가능) / 되돌릴 수 없는 커밋→결정적 엔드포인트(LLM 미경유).
  • 복합 응답=섹션: 한 어시스턴트 턴에 sections[](라벨·handled). 단발=1개.
  • WebSocket 우선안 — 스파이크 결과로 보정 가능(SSE/대안). 트랜스포트 추상화 뒤에서 교체.
  • 디자인 토큰/플레이스홀더 — 애셋 도착 시 값만 교체.
