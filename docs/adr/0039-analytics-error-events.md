# ADR-0039: 에러/폴백 분석 이벤트 추가 (지연은 운영 메트릭으로 분리)

- **상태**: 채택
- **관련**: `docs/analytics.md` §4, `docs/operations.md` §5·§8, R13

## 배경
폴백 경로(R13: `stream_interrupted`·`orchestrator_error`·품절·`upstream_unavailable`)가 많은데, **폴백률/에러율을 측정하는 이벤트가 없었다** → UX 건강을 제품 분석에서 볼 수 없었다.

## 후보안
| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A (선택)** | **`fallback_shown`·`error_shown` 추가** | 폴백률·인터럽트율(UX 건강) 가시화 | 이벤트 2종 추가 |
| B | **추가 안 함**(운영 로그로만) | 택소노미 단순 | 실패 경험이 제품 분석에 안 보임 |

## 결정
**A.** 사용자에게 폴백/에러가 **노출된 순간** FE가 emit — `fallback_shown{reason}`·`error_shown{code}`. 단, **지연(TTFB·완료시간)은 분석이 아니라 운영 메트릭**(operations §5)으로 분리(관측성/오토스케일용).

## 기각 이유
- B: 폴백/에러는 핵심 UX 신호다. 운영 로그만 보면 "사용자가 실제로 겪은 실패율·이탈 연관"을 제품 관점에서 분석할 수 없다.

## 결과/영향
폴백률을 퍼널 이탈(`flow_abandoned`)과 교차분석 가능. 지연 메트릭과의 경계(분석 vs 운영)를 analytics §4 주석에 명시.
