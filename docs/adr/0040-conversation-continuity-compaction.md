# ADR-0040: 대화 연속성 = 하이브리드 컴팩션 + 영속 메모리

- **상태**: 채택
- **관련**: `docs/operations.md` §4-1·§13, `docs/data-model.md`(`ConversationMemory`), ADR-0028, R12

## 배경
대화가 **계속 이어지는 느낌**(세션 리셋 없음)을 원한다. 그러나 컨텍스트는 무한정 커질 수 없다(토큰·비용·지연). 하드 세션 클리어는 보류하고, **맥락이 커지면 압축**해야 한다.

## 후보안
| 안 | 방식 | 장점 | 단점 |
|---|---|---|---|
| **A (선택)** | **하이브리드** — 구조화 사실 + 롤링 요약 + 최근 N턴 verbatim, 영속 메모리 rehydrate | 토큰 bounded·엔티티 정확 연속·재방문 복원, FlowState·개인화와 정합 | 추출/요약 로직 |
| B | **롤링 요약만(compaction)** | 단순·연속 | 주문ID·스펙 등 **디테일 손실** |
| C | **슬라이딩 윈도우(절단)** | 가장 쌈 | **하드 망각** → 옛 맥락 참조 시 끊김 |
| D | **대화 RAG**(전 이력 검색) | 완전 회상 | 세션별 벡터 인프라·검색 품질 |

## 결정
**A.** 3계층 컨텍스트 — ① **구조화 사실(durable)** `ConversationMemory.facts`(기기·진행 주문·추천 부품·미해결 이슈; 손실 위험 큰 항목은 요약 대신 사실로 보존) ② **롤링 요약(durable)** `summary` ③ **최근 N턴 verbatim(working)**. 컴팩션 트리거 = 토큰 임계(~70%)/N턴. **working은 휘발(`sess:{sid}` TTL), 사실+요약은 영속(DB, R12)** → 재방문 rehydrate로 연속성.

## 기각 이유
- B: 요약 단독은 주문ID·모델 등 핵심 디테일을 잃는다 → 사실 보존을 병행해야 안전.
- C: 단순 절단은 옛 맥락 참조 시 끊겨 "이어지는 느낌"을 깬다.
- D: MVP엔 세션별 벡터 인프라가 과함 → 후속 확장 후보.

## 결과/영향
세션 TTL(operations §13)은 **working 맥락에만** 적용, 연속성은 영속 메모리가 책임. 하드 세션 클리어 결정은 별도 보류.
