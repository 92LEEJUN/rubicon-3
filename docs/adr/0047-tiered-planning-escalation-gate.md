# ADR-0047: 티어드 플래닝 + 에스컬레이션 게이트 (LLM 플래너 레이턴시 예산)

- **상태**: **대체됨** → [ADR-0048](0048-llm-planner-single-router.md)(LLM 플래너 단일 라우터). 폐기 사유는 ADR-0048 "게이트를 닫은 사유(상세)" 참조 — 휴리스틱 임계 취약성·이중 경로 복잡성·목적지 추가로 전제 변화.
- **관련**: ADR-0046(조언형/행동형), ADR-0017(턴 내 병렬 보류), `specs/capability-orchestrator/`(요구사항 4·11), `test-findings.md`(F1·F2)

## 배경
LLM 플래너(요구사항 4-1)를 모든 자유텍스트 턴에 순진하게 붙이면 **첫 토큰 전에 LLM 왕복 1회가 추가**된다. 게다가 capability 실행이 순차(ADR-0017)라, 복합 턴은 `플래너(1) + 능력 N개`가 직렬로 쌓여 레이턴시가 악화된다. 한편 장문 검증(`test-findings.md`)은 규칙 분류기가 **장문·모호 턴(F1 단어 오발화, F2 미매핑 후속 의도)**에서만 부서지고, 짧거나 깨끗한 장문(예: J5 복합)은 규칙으로 충분함을 보였다.

## 결정: 규칙 1차, LLM은 에스컬레이션
- **규칙 분류기를 1차 플래너로 둔다(홉 0).** 깨끗한 턴은 LLM 홉 없이 즉답한다.
- **결정적 에스컬레이션 게이트**(`should_escalate`)가 "규칙이 부서질 신호"를 감지할 때만 LLM 플래너로 올린다. 신호:
  - `warranty_cue`·`booking_cue`·`explain_cue` — 규칙에 매핑 안 된 후속 의도(보증·예약·설명/비교/가격) 단서(F2).
  - `weak_capture` — 장문(≥45자)인데 약한 의도(general/device_status)만 잡힘(F1).
  - `compound_undersplit` — 접속사 많은 장문이 단일 capability로 과소분할.
- LLM 플래너 미연결 시엔 에스컬레이션이어도 **규칙 plan으로 폴백**(동작 불변). 판정은 `last_decision`에 기록해 **측정 가능**.
- 레이턴시 추가 완화(설계 지침): ① 결정적 섹션 먼저 스트리밍(요구사항 11-1)으로 플래너 지연을 TTFT 뒤로 숨김, ② 플래너는 짧은 구조화 출력·빠른 모델, ③ 팬아웃 병렬화는 ADR-0017 재검토 대상.

## 측정 (장문 코퍼스 8턴, `verify_multiturn_long.py`)
- **홉 0(규칙)**: A-T1(장문 단일 진단)·A-T3(주문)·B-T1(위험 장문, 결정적 안전 게이팅)·C-T1(장문 추천)·D(복합 3종) — **5/8**.
- **홉 1(LLM 필요)**: A-T2(explain·weak·undersplit)·B-T2(warranty·booking)·C-T2(explain) — **3/8**, 모두 규칙이 오분류한 턴.
- 즉, 홉은 **규칙이 틀린 턴에만** 지불 → 정확도를 사는 거래로 비용을 국한.

## 대안 / 기각
- **모든 턴 LLM 플래너** — 깨끗한 턴까지 +1홉, 명백한 퇴보로 기각.
- **순수 규칙 유지** — F1·F2(장문 문맥·후속 의도) 구조적 미해결로 기각.
- **분류+플랜+첫답 1콜 융합** — 홉은 없애나 plan 사전검증(행동형 차단·필수 보정) 약화로 보류(후속 옵션).

## 영향
- `should_escalate`/`EscalationDecision`/`CapabilityOrchestrator.decide·route` 구현(결정적). LLM 플래너 연결은 §9에서 `llm_planner` 주입으로. §2.1 봉투·기존 동작 불변(157 통과).
