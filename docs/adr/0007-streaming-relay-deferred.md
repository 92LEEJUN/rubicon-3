# ADR-0007: 스트리밍 릴레이 메커니즘 — Streams vs Pub/Sub (보류)

- **상태**: 보류
- **관련**: `docs/operations.md` §13·§14, ADR-0006·0008

## 배경
Phase B(ADR-0006)에서 워커가 만든 delta/섹션을 WS 종단(BFF)으로 중계할 메커니즘이 필요하다(채널 키 = `turn_id`).

## 후보안
| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| Redis Streams | XADD/XREAD + consumer group | **첫 토큰 유실 없음·재연결 재생·견고** | 약간 복잡 |
| Pub/Sub | 채널 발행/구독 | 단순 | **구독 전 발행분 유실·재생 불가**(구독→인큐 순서로 완화 필요) |

## 결정
**보류 — 구현 시 벤치 후 택1.** 멀티에이전트 다단계 순서 이벤트(ADR-0008)가 많아 **Streams에 유리**하지만, 최종 선택은 실측 후로 미룬다.

## 근거 / 기각 이유
- 두 안의 트레이드오프(견고성 vs 단순성)가 워크로드에 의존 → 실측 없이 확정하지 않는다.

## 결과/영향
Phase B 구현 착수 시점에 벤치마크로 확정. 멀티에이전트를 본격화하면 Streams 쪽으로 기운다.
