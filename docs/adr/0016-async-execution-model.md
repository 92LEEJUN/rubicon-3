# ADR-0016: 실행 모델 = async 전환 (순차 유지)

- **상태**: 구현됨 (PR #50)
- **관련**: `docs/operations.md` §6·§14-1, `backend/app/llm.py`·`orchestrator/legacy.py`·`api/internal.py`, ADR-0017

## 배경
BE 실 경로(HTTP `/internal/turn`)는 **sync 제너레이터 → Starlette 스레드풀** = **턴당 스레드 1개를 ~21초 점유**(스레드풀 ~40 → 동시 ~40턴 천장). 실행 모델을 어떻게 둘지.

## 후보안
| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A (선택)** | **async 전환** — AsyncOpenAI + async 세마포어, 엔드포인트 비동기 제너레이터. **실행은 순차 유지** | 스레드-당-턴 점유 제거 → 동시 처리량↑, 출력 동일, 병렬·abort 토대 | tool-loop 리팩터 |
| B | **sync 유지** — 스레드 fan-out, coarse abort | 최소 변경 | 스레드 점유 지속·천장 유지 |
| C | **하이브리드** — 일부만 async | 점진적 | 분기 복잡 |

함께 검토: **async(확장성) vs 2b(체감속도)** — 둘은 목적이 다름. async는 동시성, 2b는 단일 턴 체감.

## 결정
**A — async 전환, 순차 유지.** 병렬화(ADR-0017)는 분리·보류. async의 실익은 **동시성**이지 단일 턴 지연이 아님.

## 근거 (실측, §14-1)
단일 turn ~7.6s일 때 **4턴 동시 = ~6.2s**(순차라면 ~30s). 이벤트 루프가 LLM I/O를 겹쳐 처리. **출력은 동일**(BE 52·BFF 17 통과).

## 기각 이유
- B: 스레드-당-턴 점유가 남아 동시성 천장이 유지된다.
- C: 경로 분기로 복잡도만 늘고 이득은 부분적.

## 결과/영향
Phase A 동시성 목표(ADR-0002) 달성. 단일 턴 체감은 후속 2b로(ADR-0015), 병렬화는 보류(ADR-0017).
