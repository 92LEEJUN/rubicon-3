# 유저 시나리오 / 풀 저니 (User Scenarios)

> 요구사항(`requirements.md`)을 **end-to-end 흐름**으로 강화하고, 저니를 따라가며
> **고려하지 못한 부분(갭)** 을 발굴한다. 단일 출처는 requirements이며, 본 문서는
> 시나리오 관점의 보강과 **갭 후보**를 제시한다(갭의 요구사항 승격 여부는 §6에서 결정).
> 화면/템플릿은 `docs/wireframes.md`·`docs/response-templates.md`, 흐름은 `docs/diagrams.md` 참조.

## 3. 대안 · 분기 시나리오

- **해결 실패 → 핸드오프**(P2) — 가이드로 안 되거나 위험 → 상담원/방문(`handoff_card`·`booking`), 맥락 전달(R18).
- **부품 모호** — 후보 여럿 → `choices`로 사용자 확인, 임의 선택 금지(R4-3).
- **미연동 사용자**(P3) — 기기 데이터 없음 → 일반 안내로 폴백 + 연동 유도(R13-2). *온보딩 흐름 자체는 미정(§5-P).*
- **복합 질문**(R7) — "소리나고 필터도 주문" → 분해 → 우선순위(안전/CS) → 순차 처리.
- **흐름 전환·복원**(R6) — 가이드 중 다른 질문 → 채팅 전환(맥락 유지) → 복귀.

## 4. 엣지 · 예외 시나리오

- **외부 실패** — SmartThings 지연/오류·O2O 실패 → 폴백 안내 + 대안(R13). 대화 중단 금지.
- **권한 거부** — 카메라/갤러리 거부 → 텍스트 입력 폴백(R10·R13).
- **동의 철회 중 개인화** — `Consent.scopes` 밖 접근 거부, 개인화 제한 안내(R19).
- **오탐 흐름 전환** — 자유 입력을 의도 전환으로 오인 → 복원/되돌리기로 완화(design §6.5).
- **결제 실패** — checkout 실패 → 재시도/대안 경로. *결제 특화 복구는 미정(§5-J).*
