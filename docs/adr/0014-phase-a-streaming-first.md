# ADR-0014: Phase A 우선순위 = 스트리밍 먼저

- **상태**: 채택
- **관련**: `docs/operations.md` §6(Phase A 실행 계획), ADR-0008·0015·0016

## 배경
멀티에이전트 지연(ADR-0008, 실측 ~21s)에 대응할 Phase A 레버가 여럿이다: ① 턴 내 병렬화 ② 증분/다단계 스트리밍 ③ 단계 타임아웃·abort. 무엇부터 할지.

## 후보안
| 안 | 순서 | 장점 | 단점 |
|---|---|---|---|
| **A (선택)** | **스트리밍 먼저**(2a→…) | 저위험·즉효, 단일 경로도 이득, 멀티에이전트 체감 개선 ROI 큼 | 총 완료시간 자체는 안 줄임 |
| B | 병렬화 먼저 | 최대 지연 절감(~35%) | 복합 일관성 리스크(ADR-0017) |
| C | 견고성 먼저 | 안정성 | 즉시 체감 작음 |
| D | 한 묶음 | 한 번에 | 범위·리스크 큼 |

## 결정
**A — 스트리밍 먼저.** 이어서 병렬화·견고성을 검토(이후 보류 결정 ADR-0017·0018).

## 기각 이유
- B: 병렬화는 복합 응답 일관성 리스크가 커서 선행하기엔 위험.
- C: 견고성은 사용자 체감 개선이 작다.
- D: 범위·리스크가 한꺼번에 커진다.

## 결과/영향
스트리밍은 범위 2a만(ADR-0015)으로 착수, 이어 실행 모델 async 전환(ADR-0016).
