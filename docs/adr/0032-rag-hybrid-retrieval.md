# ADR-0032: RAG = 오류코드 정확 매칭 + 벡터 검색 하이브리드

- **상태**: 채택
- **관련**: `docs/orchestration.md` §5, `docs/architecture.md` §5(CS ACL), R16

## 배경
CS 지식은 **구조화**돼 있으면서도(오류코드→해결) 자유 증상도 처리해야 한다(R16 근거 제시).

## 후보안
| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A | **벡터 검색만** | 자유 증상 처리 | 정확한 오류코드도 근사 검색(부정확·느림) |
| B | **키-값 정확 매칭만** | 빠르고 정확 | 자유 증상·동의어 못 잡음 |
| **C (선택)** | **하이브리드** — 오류코드 정확 매칭(키) + 자유 증상 벡터 | 둘의 장점, 상위 근거 augment | 두 경로 |

## 결정
**C.** `Anomaly.error_code → Solution` 직접 조회(빠르고 정확) + 자유 증상 의미 검색(벡터)을 합쳐 상위 근거로 augment. CS는 정적·구조적이라 인제스천이 쉽다.

## 기각 이유
- A: 오류코드처럼 정확 키가 있는데 근사 검색은 부정확·낭비.
- B: 자유 증상·동의어 질의를 놓친다.

## 결과/영향
출처(`Source`)를 함께 제시(R16). 진단 에이전트(ADR-0010)의 `search_solutions`가 이 경로를 사용.
