🔀 API / 표현 계층 (BFF 역할)

BFF 필독 가이드

별도 서비스가 아니라 FastAPI 안의 계층. 화면 집계·Template 정형화·스트리밍 중계·인증 게이트. 비즈니스 로직은 갖지 않는다(조합·변환·중계만).

책임필독 문서계약다이어그램주의

01내 책임 / 경계

✅ 내가 한다

  • 화면 단위 aggregation(예: home_summary)
  • 도메인/LLM 출력 → Template/MessageSection 정형화
  • LLM·오케스트레이터 스트림 → WebSocket 중계
  • 인증/세션 게이트(토큰 검증·조용한 재인증)
  • 외부 실패 → 폴백 응답 정규화(R13)
  • 카드 탭 /surface → bridge/panel 응답 형태 구성

🚫 내가 안 한다

  • "LLM이냐 도메인이냐" 라우팅 판단 → 오케스트레이터
  • 도메인 비즈니스 로직 → 도메인 서비스
  • 도메인 DB 직접 접근 → 서비스/Port 경유
  • 되돌릴 수 없는 커밋 자체 처리 → 도메인+ActionGate
이음새(seam) 유지. 지금은 FastAPI에 흡수돼 있지만, 비즈니스 로직을 안 가지므로 2nd 클라이언트·독립 스케일 필요 시 떼어내기 쉽게(architecture §9).

03내가 빌드할 계약

  • WS /chat — user_message/interaction_reply 수신, delta/section/flow/done 중계(api-contract §2.1)
  • 결정적 엔드포인트 — /devices·/cart·/orders·/bookings·/handoff·/history·/surface req/resp(§2.2·§2.3)
  • aggregation — 여러 도메인 서비스 결과를 home_summary 등으로 조합
  • 폴백 정규화 — {code, message, fallback} (R13)
도메인 호출은 인프로세스 함수(HTTP 아님). 데이터는 외부=Port / 내부=Repository (api-contract §1).

04핵심 다이어그램

  • 요청 라우팅(architecture §8) — 자유텍스트/대화형CTA/커밋 3갈래
  • diagrams.md — 메인 시퀀스 · 주문 확인 게이트 · 선제 파이프라인 · 분석 파이프라인
  • FastAPI 내부 계층(architecture §9) — API/표현 → 오케스트레이션 → 도메인 → Port

05주의 / 알아둘 결정

  • 단일 진입점 = FastAPI. 별도 BFF 배포 없음(흡수). 트리거 발생 시 분리 검토.
  • 커밋만 LLM 미경유 — 대화형 CTA는 /chat 재진입(LLM 가능). "CTA=결정적"이 아니라 "커밋=결정적".
  • 스트리밍 우선 — 모든 응답 점진 전달. 복합은 section 청크 순서대로 중계.
  • 비차단 분석 — 분석 emit이 사용자 흐름을 막지 않게, 동의 게이트.
