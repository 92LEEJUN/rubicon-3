# ADR-0006: Phase B 무상태 워커 + Redis 토폴로지

- **상태**: 채택(설계)
- **관련**: `docs/operations.md` §13, ADR-0002·0003

## 배경
Phase B(ADR-0002)에서 수평확장을 하려면 상태를 어디에 두고 워커를 어떻게 분리할지 정해야 한다.

## 후보안
| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A (선택)** | **BFF가 WS 종단·릴레이, BE는 무상태 워커, Redis가 상태/락/레이트리밋/잡큐/릴레이** | 워커 무상태 → 증설·크래시 복구(XCLAIM), 3계층 유지 | Redis 의존 |
| B | BE 워커가 세션 상태 보유 | 단순 | 수평확장·장애 복구 어려움(상태 고착) |

## 결정
**A.** `client ⇄ [BFF: WS 종단] ⇄ Redis ⇄ [BE: 무상태 워커] ⇄ DB`.
- 세션 격리 `sess:{sid}`(TTL 30m 슬라이딩) · 세션락 `lock:turn:{sid}`(SET NX PX, ADR-0003)
- 토큰버킷 `rl:openai:*`·`rl:user:*`(Lua 원자적) · 잡큐 `q:turns`(Streams + consumer group)
- 워커 크래시 → pending → **XCLAIM 재처리** 또는 DLQ.

## 기각 이유
- B: 상태를 워커에 두면 증설·복구가 어렵다(무상태화가 수평확장의 전제).

## 결과/영향
스트리밍 릴레이 메커니즘은 별도 보류(ADR-0007). 토큰버킷 세부·TTL·하드캡 실측값은 구현 단계.
