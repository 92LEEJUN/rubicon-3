# ADR-0002: 동시성 채택 경로 A(인프로세스)→B(Redis), C·D 보류

- **상태**: 채택
- **관련**: `docs/operations.md` §6, ADR-0001·0006

## 배경
2-플레인(ADR-0001)을 어떤 인프라로 구현할지. 동시성 제한·큐·레이트리밋·스트리밍 릴레이가 필요하고, MVP는 인프라 부담을 최소화해야 한다.

## 후보안
| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A (선택, 즉시)** | **인프로세스** — `asyncio` 세마포어로 LLM 동시 호출 상한 + 인메모리 큐 | 인프라 0, 즉시 | 단일 프로세스·비내구성 |
| **B (선택, 목표)** | **Redis** — 세션 격리(TTL)·토큰버킷 레이트리밋·잡큐·스트리밍 릴레이 | 무상태 수평확장·내구성 | Redis 운영 |
| C (보류) | **Kafka** 이벤트 백본(알림·주문·분석·미디어) | 내구성·고처리량·순서·재처리 | 운영 부담·지연↑, **인터랙티브 부적합** |
| D (보류) | **매니지드 서버리스**(SQS FIFO+Lambda / Cloud Pub/Sub) | 운영 최소·오토스케일 | 벤더 락인·**스트리밍 별도 설계**·콜드스타트 |

## 결정
**A→B를 실제 구현 대상**으로 한다. C·D는 **비동기 평면이 커질 때의 후보**(지금 도입 X).

## 기각 이유
- C: 인터랙티브 응답 경로에 두면 지연·복잡↑. 이벤트량 급증·다중 소비자·감사 요구가 생기면 그때.
- D: 벤더 락인 + 스트리밍을 따로 설계해야 함 + 콜드스타트.

## 결과/영향
Phase A는 이미 착수(LLM 세마포어+백오프, async 전환 ADR-0016). Phase B 토폴로지는 ADR-0006.
