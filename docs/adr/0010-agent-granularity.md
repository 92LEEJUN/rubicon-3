# ADR-0010: 에이전트 그래뉼래리티 = 중간 (진단·커머스만 에이전트)

- **상태**: 채택
- **관련**: `docs/agents.md` §2

## 배경
무엇을 **에이전트**(자체 LLM 추론 루프)로 두고 무엇을 **tool**(결정적 호출)로 둘지. 과분할하면 LLM 홉이 늘어 지연·비용이 커진다.

## 후보안
| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A | **도메인 분리** — 진단·커머스·추천·핸드오프 + 슈퍼바이저 + 리뷰 | 역할 명확·독립 확장 | LLM 홉·비용↑ |
| B | **최소** — 슈퍼바이저 + 범용 워커 + 리뷰, 도메인은 tool | 홉·비용↓ | 전문화↓ |
| **C (선택)** | **중간** — 진단·커머스만 에이전트, 추천·핸드오프·이력은 tool | 다단계 추론 필요한 곳만 에이전트 → 홉 억제 + 전문화 | 절충 |

## 결정
**C — 중간.** 에이전트: Supervisor·Diagnosis·Commerce·Review(조건부). tool: `get_recommendations`(R8)·booking(R18)·`get_history`(R12)·DB 조회.

## 기각 이유
- A: 추천·핸드오프·이력처럼 결정적 조회/게이트 성격까지 에이전트로 두면 LLM 홉·비용이 불필요하게 커진다.
- B: 진단(상태+증상→해결)·커머스(매칭+초안+게이트)는 다단계 추론이라 범용 워커로는 전문화가 약하다.

## 결과/영향
프롬프트는 4개 에이전트만 정의(ADR-0013, `prompts.py`). 다이어그램은 `docs/diagrams.md` 멀티에이전트 그래프.
