# ADR-0001: 인터랙티브/비동기 2-플레인 분리

- **상태**: 채택
- **관련**: `docs/operations.md` §6, `docs/architecture.md` §7

## 배경
다량 동시 메시지를 처리해야 한다. 그런데 **잡 큐와 스트리밍은 상충**한다 — 잡 큐에 태우면 LLM 토큰을 같은 연결로 되돌리는 경로가 끊긴다. 채팅 응답(저지연 스트리밍)과 후처리(알림·분석·미디어)를 한 메커니즘으로 묶기 어렵다.

## 후보안
| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A | 단일 큐로 모든 작업 처리 | 단순·통일 | **스트리밍 토큰 반환 경로 끊김**, 채팅 지연↑ |
| **B (선택)** | **2-플레인 분리** — 인터랙티브(WS 스트리밍) + 비동기(내구성 이벤트) | 채팅은 같은 연결로 토큰 반환(저지연), 후처리는 내구성·재처리 | 두 경로 운영 |

## 결정
**B — 2-플레인.** 인터랙티브 평면(채팅 turn: WS → 동시성 제한 워커 → LLM 스트림 → 같은 연결 반환) / 비동기 평면(선제 알림·주문 후처리·분석·미디어: 내구성 큐).

## 기각 이유
- A: 잡 큐는 토큰 반환 경로와 상충 → 인터랙티브 스트리밍 UX를 해친다.

## 결과/영향
이후 모든 동시성·큐잉 결정(ADR-0002·0006)이 이 분리 위에 선다. "채팅 경로엔 무거운 큐를 두지 않는다"가 기본 원칙.
