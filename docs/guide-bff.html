🔀 API / 표현 계층 (BFF 역할)

BFF 완성 가이드

FastAPI 안의 계층 — 집계·정형화·스트리밍 중계·인증 게이트. 비즈니스 로직은 갖지 않는다. 이 문서 하나로 책임·계약이 완결된다.

책임계층라우팅/chat엔드포인트집계·정형화선제분석폴백주의

01책임 / 경계

✅ 한다

  • 화면 단위 aggregation(예: home_summary)
  • 도메인/LLM 출력 → Template/MessageSection 정형화
  • LLM·오케스트레이터 스트림 → WebSocket 중계
  • 인증/세션 게이트(토큰 검증·조용한 재인증)
  • 외부 실패 → 폴백 응답 정규화(R13)
  • 카드 탭 /surface → bridge/panel 응답 구성

🚫 안 한다

  • "LLM이냐 도메인이냐" 라우팅 판단 → 오케스트레이터
  • 도메인 비즈니스 로직 → 도메인 서비스
  • 도메인 DB 직접 접근 → 서비스/Port 경유
  • 되돌릴 수 없는 커밋 자체 처리 → 도메인+ActionGate

02내부 계층 (단일 FastAPI)

[API / 표현 계층]  ← 내 책임: aggregation · Template 변환 · 스트리밍 중계 · 인증 게이트
       │  (인프로세스 함수 호출, HTTP 아님)
[오케스트레이션]   ← 의도 분류 · 흐름 · 세션 · tool 조합
       │
[도메인 서비스]    ← 비즈니스 로직
       │
[어댑터(Port)]     ← Mock↔실 (외부) / Repository (내부 데이터)
별도 BFF 배포 없음(FastAPI 흡수). 비즈니스 로직을 안 가지므로 이음새(seam) 유지 → 2nd 클라이언트(웹)·독립 스케일·팀 분리 시 떼어내기 쉽게. 분리 시 집계·정형화·중계·인증게이트→BFF, 도메인·Port→도메인 BE 잔류.

03요청 라우팅 (BE가 소유)

FE는 상호작용 유형으로 채널만 고름. 채널 안 LLM-vs-도메인 판단은 오케스트레이터.

상호작용채널LLM
자유 텍스트·멀티모달/chat → 오케스트레이터BE가 결정(불투명)
대화형 CTA(제안 칩·회신·설명 요청)/chat 재진입가능(흐름 재개)
되돌릴 수 없는 커밋(결제·주문·예약 확정)결정적 엔드포인트미경유 + ActionGate(R17)
"CTA=결정적"이 아니라 "커밋=결정적". LLM 미경유 보장은 커밋 자체에 한정 — 커밋 주변 요약/후속은 LLM 생성 가능.

04WebSocket /chat 중계

# 수신
user_message      { session_id, text, media[], screen_context }
interaction_reply { session_id, ref, kind, payload }

# 송신(스트림 중계) — 오케스트레이터 출력을 청크로
delta   { text }
section { section: MessageSection }     # 복합이면 의도 우선순위 순서대로 여러 번
flow    { active_flow }
done    { message_id }
error   { code, fallback }

MessageSection = { label, intent, template:Template, ctas:[Cta], handled }

06집계 · 정형화 (내 핵심)

  • aggregation — 홈은 여러 도메인 서비스 결과를 home_summary로 조합: alerts(device_status)+recommendations(product)+shortcuts.
  • 정형화 — 도메인/LLM 출력 → Template/Cta/MessageSection으로 변환. 복합은 의도별 섹션.
  • 중계 — 오케스트레이터 스트림을 WS 청크로 변환·전달.
  • 인증 게이트 — 진입 토큰 검증, 만료 시 조용한 재인증(백그라운드 재발급, 실패만 안내).

07선제(Proactive) 파이프라인

사용자 요청 없이 시스템이 시작(이상·소모품·알림). 라우팅(§3)과 별개.

텔레메트리(폴링/이벤트) → 이상·임계치 판정 → 알림 생성·집약
  → {빈도·중요도 R26} → 우선순위·다중기기 R27 → {옵트인·동의 R20·R19}
  → 허용? AlertPort 전달(인앱/푸시) : 발송 안 함
  → 사용자 탭 → /chat(reactive 전이, 맥락 주입)

실 이벤트: SmartThings 구독 webhook(서명 검증)은 인바운드 ingress(별도). MVP는 폴링/인앱 Mock.

08분석 파이프라인

FE 이벤트(screen·cta·flow) + BE 이벤트(order_confirmed·notification_*)
  → {동의·가명화 R19} → AnalyticsPort → sink(MVP 로그/실 플랫폼) → 퍼널·전환·리텐션

비차단 — 분석 emit이 사용자 흐름을 지연·중단시키지 않음. 동의 없으면 수집 안 함.

09에러 / 폴백 정규화 (R13)

모든 외부 실패를 클라이언트 계약으로 정규화. 대화 전체 중단 금지.

표준 에러:  { code, message, fallback: Template | None }
상황처리
SmartThings 실패/미연동일반 안내 폴백 + 연동 유도
O2O/결제 실패보류 + 재시도 CTA
CS 미발견 / 신뢰도 낮음단정 금지 → 핸드오프(R18) 안내
LLM 지연/타임아웃상태 표시 + 대기/재시도/취소(R14)
세션 만료조용한 재인증, 실패만 재로그인 안내

10주의 / 결정

  • 도메인 호출은 인프로세스 함수(HTTP 아님). 외부=Port / 내부=Repository.
  • 라우팅 판단 안 함 — 오케스트레이터에 위임, 나는 중계.
  • 스트리밍 우선 — 복합은 section 청크 순서대로.
  • 커밋만 LLM 미경유 + ActionGate(R17).
  • seam 유지 — 비즈니스 로직 금지(조합·변환·중계만).
