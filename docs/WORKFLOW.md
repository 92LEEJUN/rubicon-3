# 작업 워크플로우 가이드

이 레포는 **스펙 기반(spec-driven) 개발**을 사용합니다.
모든 작업은 코드를 작성하기 전에 3종 문서를 먼저 만들고, 단계적으로 진행합니다.

이 문서는 사람을 위한 안내입니다. 에이전트(Claude)용 규칙은 루트의
[`CLAUDE.md`](../CLAUDE.md) 에 있습니다.

## 왜 이렇게 하나요?

- **무엇을 만들지(requirements)** 를 먼저 합의하면, 잘못된 것을 만드는 일을 줄입니다.
- **어떻게 만들지(design)** 를 미리 정하면, 구현 중 헤매는 시간을 줄입니다.
- **작업 단위(tasks)** 로 쪼개면, 진행 상황을 추적하고 리뷰하기 쉽습니다.

## 3단계 한눈에 보기

| 단계 | 파일 | 질문 | 핵심 |
|------|------|------|------|
| 1. 요구사항 | `requirements.md` | **무엇을 / 왜?** | User Story + 수용기준(EARS) |
| 2. 설계 | `design.md` | **어떻게?** | 아키텍처, 컴포넌트, 데이터 모델 |
| 3. 작업 | `tasks.md` | **어떤 순서로?** | 검증 가능한 체크리스트 |

## 새 작업 시작하기

1. `specs/<작업명>/` 폴더를 만듭니다. (작업명은 kebab-case)
2. `specs/_template/` 의 세 파일을 복사해 넣습니다.
3. `requirements.md` 부터 채웁니다. → 합의 후 `design.md` → 그 다음 `tasks.md`.
4. `tasks.md` 의 항목을 하나씩 구현하며 `[x]` 로 체크합니다.

```
specs/
├─ _template/            # 복사해서 쓰는 템플릿
│  ├─ requirements.md
│  ├─ design.md
│  └─ tasks.md
└─ user-login/           # 작업 예시
   ├─ requirements.md
   ├─ design.md
   └─ tasks.md
```

## 각 문서 작성 팁

### requirements.md
- 구현 방법은 쓰지 않습니다. **무엇이 필요한지**만 적습니다.
- 수용기준은 나중에 "이 요구사항이 충족됐나?"를 **검증할 수 있게** 씁니다.
  - 좋음: `로그인에 5회 실패할 때, 시스템은 계정을 10분간 잠가야 한다.`
  - 나쁨: `로그인이 안전해야 한다.` (검증 불가)

### design.md
- 각 설계 결정이 어떤 요구사항을 위한 것인지 연결합니다.
- 대안을 검토했다면 왜 그 안을 선택했는지 짧게 남깁니다.

### tasks.md
- 한 항목은 한 번에 리뷰 가능한 크기로 쪼갭니다.
- 각 항목 끝에 관련 요구사항 번호를 답니다. 예: `(요구사항 2)`

## 문서 언어
모든 스펙 문서는 **한국어**로 작성합니다. (코드/기술 용어는 영어 가능)
