# ADR-0009: 멀티에이전트 제어 패턴 = 슈퍼바이저-워커

- **상태**: 채택
- **관련**: `docs/agents.md` §1, `docs/orchestration.md` §1·§10

## 배경
멀티에이전트를 어떤 토폴로지로 조율할지. MVP는 단일 오케스트레이터 tool-loop이지만 복잡도가 커지면 확장이 필요하다.

## 후보안
| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A (선택)** | **슈퍼바이저-워커** — 중앙 슈퍼바이저가 서브에이전트/tool을 위임·조립 | 통제 쉬움, "워크플로=코드가 루프 제어"와 정합, 디버깅 용이 | 슈퍼바이저가 병목 가능 |
| B | **고정 파이프라인**(plan→retrieve→act→review 고정) | 단순·예측가능 | 복합/분기 유연성↓ |
| C | **네트워크/피어**(에이전트끼리 호출) | 유연 | **통제·디버깅 어려움·지연↑**, 비결정적 |

## 결정
**A — 슈퍼바이저-워커.** 슈퍼바이저가 intent별 필요한 워커만 동적 위임하고 결과를 조립.

## 기각 이유
- B: 고정 단계라 복합 질문(R7)·분기에 유연성이 떨어진다.
- C: 자율 네트워크는 통제·디버깅·지연이 커지고 출력이 비결정적 → 운영 리스크.

## 결과/영향
워커 구성은 ADR-0010(그래뉼래리티), 리뷰는 ADR-0011, 반복 여부는 ADR-0012로 이어진다.
