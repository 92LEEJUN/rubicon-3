게이트웨이 — 큰 카테고리

BFF는 클라이언트와 도메인 백엔드 사이의 얇은 게이트웨이입니다. 인증/SSO·중계·실시간 릴레이·응답 정형·보안·관측·분석을 책임지고, 비즈니스 로직은 BE에 위임합니다. 아래는 bff/gateway/ 모듈을 큰 카테고리로 묶은 것입니다.

FEHTTP·WS 요청 + 토큰/게스트
→
BFF Gateway① 신원 해석 → ② 중계/릴레이 → ③ 응답 정형 → ④ 보안·관측·분석
→
BE/internal/* 도메인 API

1 인증 · 신원 (SSO / 게스트)

gateway/auth.py — 토큰 검증·신원 해석·BE 헤더 포워딩. 실 전환: 삼성계정 SSO·세션 TTL·조용한 재인증.

Identity 해석

요청 → 로그인/게스트 신원 결정. 토큰은 도메인 모델에 저장하지 않음(NFR).

  • 토큰 있음→ user (MOCK_USER_ID) 로그인 컨텍스트
  • 토큰 없음→ guest (guest_token 쿼리/쿠키 또는 신규 발급)
  • BE 포워딩X-User-Id / X-Guest-Token 헤더로 신원 중계

커밋 게이트 (위임)

게스트도 자문·대화는 허용. 주문/예약 커밋은 BFF가 막지 않고 BE의 401 LoginRequired를 그대로 중계(공유 계약).

게스트→로그인 머지401/409 패스스루

실 SSO·세션은 후속(deferred).

3 실시간 채팅 릴레이

WebSocket /chat — FE↔BE 스트림 양방향 릴레이. 섹션 봉투(§2.1)를 그대로 흘려보냄.

WS /chat 스트리밍 릴레이 신원 핸드셰이크

FE 메시지(text·screen_context·신원) → BE /internal/turn WS로 중계 → 청크(delta/section)를 FE로 되돌림. 끊김 무노출·점진 렌더.

4 응답 정형 · 폴백 (계약)

gateway/transform.py — 업스트림 실패를 클라이언트 계약(폴백 응답)으로 정규화(R13). 대화·화면 중단 금지.

BE/네트워크 오류 → 표준 폴백 메시지·템플릿으로 변환해 중계. FE는 항상 일관된 봉투를 받는다(계약 3계층 동기화).
