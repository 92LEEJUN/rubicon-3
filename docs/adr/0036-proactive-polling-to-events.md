# ADR-0036: 선제 파이프라인 = 폴링(MVP) → 이벤트 webhook(실), 동일 정규화

- **상태**: 채택
- **관련**: `docs/architecture.md` §10, ADR-0021

## 배경
이상 감지·선제 알림(R2·R5·R20)은 기기 텔레메트리를 받아야 한다. MVP에서 실시간 이벤트 인프라를 갖추긴 어렵다.

## 후보안
| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A | **폴링 고정** | MVP 단순 | 실시간성↓·rate limit |
| B | **이벤트 구독(webhook) 즉시** | 실시간 | 인프라·서명검증·수명주기 복잡(MVP 과함) |
| **C (선택)** | **MVP 폴링 → 실 전환 시 이벤트**, 둘을 **같은 내부 "기기 이벤트"로 정규화** | 단계적, 이상감지 로직 불변 | 두 수신 경로 |

## 결정
**C.** MVP는 SmartThings 폴링/임계치 + 인앱 Mock(AlertPort). 실 전환은 **구독 webhook**(HTTP Signature 검증·challenge·배치 이벤트) → ACL이 도메인으로 정규화. **폴링과 구독이 같은 정규화를 거치므로 이상감지·알림 로직은 불변.**

## 기각 이유
- A: 폴링 고정은 실시간성·rate limit 한계.
- B: 서명검증·sink 수명주기 등은 MVP에 과한 복잡도.

## 결과/영향
webhook ingress는 `/chat`과 무관한 BE 도메인 인바운드(BFF 인증 게이트와 별도 서명검증). 토큰 교체(ADR-0021)와 같은 격리 철학.
