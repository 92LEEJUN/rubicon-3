# ADR-0015: 증분 스트리밍 범위 = 2a만 (2b 후속)

- **상태**: 구현됨 (PR #49)
- **관련**: `docs/operations.md` §9, `bff/gateway/backend_client.py`·`main.py`, ADR-0014

## 배경
스트리밍 먼저(ADR-0014)를 어디까지 구현할지. 두 하위 항목이 있다 — **2a** BFF 버퍼링→증분 포워딩, **2b** 결정적 프리페치 + 다단계 섹션(첫 섹션 ≤2~3s).

## 후보안
| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A (선택)** | **2a만** — BFF가 청크 도착 즉시 포워딩 | BFF-only·저위험·즉효, 단일 경로도 이득 | 첫 섹션 빠르게 띄우는 효과(2b)는 아직 |
| B | **2a+2b** | 첫 섹션 ≤2~3s 체감 | 오케스트레이터 재구성·스트림 계약 변경(리스크↑) |

## 결정
**A — 2a만.** `backend_client.turn_stream`(async gen)로 도착 즉시 WS 중계, 버퍼링 제거. 부분 전송 후 실패는 `stream_interrupted`로 마감(operations §8). 2b(결정적 프리페치/다단계)는 후속.

## 기각 이유
- B: 2b는 오케스트레이터·스트림 계약을 건드려 리스크가 크다 → 저위험 2a를 먼저 출하.

## 결과/영향
구현·머지 완료(PR #49). 첫 섹션 ≤2s 목표는 후속 2b에서. async 전환(ADR-0016)과 독립(2a는 BFF-only).
