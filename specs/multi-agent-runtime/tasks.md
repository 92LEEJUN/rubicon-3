# 작업 (Tasks)

> [design.md](./design.md) 를 실제 구현으로 나눈 체크리스트.
> 각 항목은 작고 검증 가능한 단위로 쪼개고, 끝에 관련 요구사항 번호를 표기한다.
> 완료한 항목은 `[x]` 로 체크한다.

## 작업 목록

- [ ] 1. 멀티에이전트 런타임 모듈 골격 생성 _(요구사항 1, 7)_
  - [ ] 1.1 `backend/app/orchestrator/runtime.py` 신규 — `astream_multiagent(message, screen_context, memory)` async 제너레이터 시그니처를 `legacy.astream_turn`과 동일하게 둔다.
  - [ ] 1.2 모든 LLM 호출을 `llm.achat_completion`(async 세마포어·백오프) 경유로 작성, 실행은 순차 유지(ADR-0017 비범위 명시). _(요구사항 7)_

- [ ] 2. Supervisor 단계 — 분해·우선순위·위임 _(요구사항 1)_
  - [ ] 2.1 `aclassify`(legacy `INTENT_SCHEMA` 재사용)로 의도 분해(구조화 출력). _(요구사항 1-1)_
  - [ ] 2.2 `core._PRIORITY` 정렬 재사용 — 안전/CS 먼저, order 뒤. _(요구사항 1-2)_
  - [ ] 2.3 의도→워커 매핑(진단/커머스=워커, 추천·예약·이력=직접 tool). _(요구사항 1-3, 1-4)_
  - [ ] 2.4 주문 등 민감 의도에 규칙 가드레일 재검증 추가. _(요구사항 1-5)_

- [ ] 3. Diagnosis 워커 배선 _(요구사항 2)_
  - [ ] 3.1 async `_agent(DIAGNOSIS_PROMPT, allowed=("get_device_status","search_solutions"))` 구현. _(요구사항 2-1)_
  - [ ] 3.2 산출에서 `required_parts`·`device_status` 추출 → 핸드오프 컨텍스트 적재. _(요구사항 2-3)_
  - [ ] 3.3 tool 근거·출처 표기, 위험 단계 경고 보존(프롬프트 규약 검증). _(요구사항 2-2, 2-4)_

- [ ] 4. Commerce 워커 배선 (커밋 게이트) _(요구사항 3)_
  - [ ] 4.1 async `_agent(COMMERCE_PROMPT, allowed=("match_parts",))` 구현. _(요구사항 3-1)_
  - [ ] 4.2 명시 부품 없으면 Diagnosis `required_parts` 이어받기(core `carried_parts` 정합). _(요구사항 3-2)_
  - [ ] 4.3 커밋은 ActionGate(`POST /internal/orders` 409 경로) 위임 — 워커는 초안까지. _(요구사항 3-3)_
  - [ ] 4.4 품절 시 입고 알림/대체 폴백 경로 확인. _(요구사항 3-4)_

- [ ] 5. 조건부 Review 게이트 _(요구사항 4)_
  - [ ] 5.1 `should_review(intents, sections) -> bool` 결정 함수 — 안전(R23)·커밋(R17)·불확실(R16) 발동, 그 외 스킵. _(요구사항 4-1, 4-2)_
  - [ ] 5.2 발동 시 `REVIEW_PROMPT` 검수 호출, `pass`면 방출. _(요구사항 4-3)_
  - [ ] 5.3 위반 시 보정/차단·사람 연결, 재계획 루프 금지(단일 패스). _(요구사항 4-4)_

- [ ] 6. 다단계 진행 스트리밍 _(요구사항 5)_
  - [ ] 6.1 빠른 DB/결정적 섹션을 먼저 방출(첫 의미있는 섹션 ≤ 2~3s). _(요구사항 5-1)_
  - [ ] 6.2 단계 순서(진단 → 커머스 → 조건부 리뷰)대로 `section`/`delta` 점진 방출. _(요구사항 5-2)_
  - [ ] 6.3 §2.1 봉투(`section`/`delta`/`flow`/`done`/`error`)만 사용. _(요구사항 5-3)_
  - [ ] 6.4 진행 문구는 답변 중심만(시스템·대기·순번 비노출). _(요구사항 5-4)_

- [ ] 7. 디스패치 공존 (LLM_BACKED + 멀티에이전트 토글) _(요구사항 6)_
  - [ ] 7.1 `internal.py` `_multiagent()` env 토글 추가(매 호출 평가, `_llm_backed` 패턴). _(요구사항 6-4)_
  - [ ] 7.2 `_stream_turn`에 멀티에이전트 분기 추가 — off면 결정적/단일 tool-loop 유지. _(요구사항 6-1, 6-2)_
  - [ ] 7.3 세 경로 모두 동일한 §2.1 봉투 방출 보장. _(요구사항 6-3)_

- [ ] 8. 단계별 실패·부분 폴백 _(요구사항 8)_
  - [ ] 8.1 워커 단계별 try/except·단계 타임아웃 — 실패 단계만 폴백/생략, 부분결과 유지. _(요구사항 8-1)_
  - [ ] 8.2 Review 실패 시 초안 안전 방출. _(요구사항 8-2)_
  - [ ] 8.3 턴 전체 회복 불가 시 `error` 봉투(비중단). _(요구사항 8-3)_

- [ ] 9. 컴패니언 메모리 정합 _(요구사항 9)_
  - [ ] 9.1 `memory`(요약+사실)를 `_memory_note` 재사용으로 Supervisor/워커 system 주입. _(요구사항 9-1)_
  - [ ] 9.2 워커엔 스코프된 부분만 전달(전체 이력 금지). _(요구사항 9-3)_
  - [ ] 9.3 턴 종료 후 `_stream_and_record`의 `record_turn` 경로가 멀티에이전트에도 적용됨을 확인. _(요구사항 9-2)_

- [ ] 10. Mock/결정적 테스트 _(요구사항 10)_
  - [ ] 10.1 슈퍼바이저 위임 매핑 단위 테스트(규칙 분류기·분류 스텁 주입). _(요구사항 10-1)_
  - [ ] 10.2 리뷰 게이트 발동/스킵 결정 테스트(LLM 미발동). _(요구사항 10-2)_
  - [ ] 10.3 워커·tool Mock 단위 + `required_parts` 핸드오프 테스트. _(요구사항 10-3)_
  - [ ] 10.4 다단계 스트리밍 청크 종류·순서 단언 테스트. _(요구사항 10-4)_
  - [ ] 10.5 토글 off 결정적 경로 회귀 테스트(봉투 동일). _(요구사항 6)_
  - [ ] 10.6 부분 폴백(워커 예외) 비중단 테스트. _(요구사항 8)_
