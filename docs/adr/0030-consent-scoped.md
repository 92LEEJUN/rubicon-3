# ADR-0030: 동의(Consent) = 기능별 scope 세분화

- **상태**: 채택
- **관련**: `docs/data-model.md` §3, `docs/llm-policy.md` §5, R15·R19

## 배경
개인화·분석·기기 데이터 사용 권한을 어떻게 모델링할지. 사용자가 일부만 허용할 수 있어야 한다.

## 후보안
| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A | **포괄 동의**(전부 또는 아무것도) | 단순 | 일부만 허용 불가, 프라이버시 거침 |
| **B (선택)** | **기능별 scope 키** | 기능 단위 독립 제어, 폴백 명확 | scope 관리 |

## 결정
**B.** `Consent.scopes` = `device_data`·`personalization`·`engagement`·`analytics`. **각 기능은 자기 키가 있어야** 개인 데이터를 쓴다(없으면 비활성·일반 폴백). 선제 알림은 `Notification.opted_in`으로 **별도 제어**(scope 아님).

## 기각 이유
- A: 포괄 동의는 "기기는 되고 분석은 싫다" 같은 선택을 못 한다(프라이버시·R19 위반 소지).

## 결과/영향
개인화 컨텍스트 조립(operations §4)·캐시 키(operations §2)·분석 수집 게이트가 모두 scope를 참조한다.
