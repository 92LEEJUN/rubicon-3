# 요구사항 (Requirements) — 칩 한글 기기명 라벨

## 개요
제안 칩·기기 라벨이 내부 식별자(영문, 예: `washer`·`dryer`)를 그대로 노출해 한국어 사용자에게
이질적이다. 본 작업은 **표시 라벨을 한글 기기명**(washer→세탁기)으로 매핑해 즉시 UX를 개선한다.
로드맵 Q1 Quick Win(칩 라벨 한글 기기명, S). 칩/라벨 표현 계약은
[response-templates](../../docs/response-templates.md)(제안 칩·CTA)를 따른다. 내부 식별자(라우팅
키)는 **불변**이며 표시 라벨만 바꾼다. design/tasks는 후속.

## 요구사항 목록

### 요구사항 1: 한글 표시 라벨 매핑
**User Story:** 한국어 사용자로서, 칩·기기 라벨이 한글 기기명으로 보이기를 원한다, 그래서 자연스럽게
이해할 수 있다.

**수용기준 (Acceptance Criteria):**
1. WHEN 기기 종류 식별자(`washer`·`dryer`·`refrigerator` 등)를 사용자에게 칩/라벨로 표시할 때 THEN 시스템은 **대응하는 한글 기기명**(세탁기·건조기·냉장고 등)을 표시해야 한다 (SHALL).
2. IF 식별자에 대응하는 한글 라벨이 정의되지 않았으면 THEN 시스템은 **원 식별자를 폴백**으로 표시해야 한다(빈 라벨 금지) (SHALL).
3. 라벨 매핑은 단일 출처(매핑 테이블/리소스)에서 관리되어야 한다 (SHALL).

### 요구사항 2: 식별자·라우팅 불변
**User Story:** 유지보수자로서, 표시 라벨 변경이 내부 라우팅·계약을 바꾸지 않기를 원한다, 그래서
회귀가 없다.

**수용기준 (Acceptance Criteria):**
1. WHEN 표시 라벨을 한글로 바꿀 때 THEN 시스템은 **칩 액션·라우팅에 쓰는 내부 식별자·값**을 변경하지 않아야 한다 (SHALL). _(표시(label)와 값(value) 분리)_
2. WHEN 사용자가 한글 라벨 칩을 탭하면 THEN 시스템은 기존과 **동일한 동작/라우팅**을 수행해야 한다 (SHALL).
3. BE 응답 계약·CTA kind는 불변이어야 한다(표시 매핑은 표현 계층) (SHALL).

### 요구사항 3: 결정성·회귀
**User Story:** 유지보수자로서, 라벨 매핑이 결정적이고 테스트 가능하기를 원한다.

**수용기준 (Acceptance Criteria):**
1. WHEN 동일 식별자가 주어지면 THEN 시스템은 항상 동일한 한글 라벨을 반환해야 한다 (SHALL).
2. 기존 칩/라우팅 관련 테스트는 통과를 유지해야 한다 (SHALL).
