# ADR-0042: always-present 컴패니언 — 선제 재관여 = 엄격 게이트

- **상태**: 채택
- **관련**: `specs/always-present-companion/`, `docs/architecture.md` §10, ADR-0040·0028, R25·R26·R19

## 배경
"**언제든 에이전트가 곁에 있다**"는 느낌을 주려 한다. 연속성(ADR-0040) 위에 **선제 재관여**(에이전트가 먼저 말 걺)가 그 느낌을 가장 강하게 주지만, **과잉 메시지는 피로·신뢰 하락**으로 직결된다(역효과).

## 후보안
| 안 | 자세 | 장점 | 단점 |
|---|---|---|---|
| A | **이어가기만(반응형)** — 사용자가 열 때만 응대, 선제 없음 | 가장 안전·무피로 | "곁에 있음"이 약함 |
| **B (선택)** | **선제 + 엄격 게이트** — 가치 있을 때만, R26 빈도·동의 엄수 | 곁에 있음 ↔ 피로 균형 | 게이트 로직 필요 |
| C | **적극 선제** — 메모리 기반 빈번한 먼저-관여 | 강한 동반감 | 피로·옵트아웃·신뢰 하락 리스크↑ |

## 결정
**B.** 선제는 **트리거(open-loop 후속·부품 입고·R25 해결확인 시점)** 가 있을 때만 생성하고, **게이트 순서**로 거른다:
`Consent/opted_in → R26 빈도/중요도 → 가치(불확실·중복이면 억제) → R27 다중기기 묶음`. 통과분만 AlertPort(§10), 탭 시 reactive 전이.

## 기각 이유
- A: 안전하지만 "언제든 곁에"라는 제품 비전을 충족 못 함(순수 수동).
- C: 빈번한 선제는 알림 피로·옵트아웃을 유발해 **오히려 신뢰를 깎는다**(R26 취지 위반).

## 결과/영향
컴패니언 스펙(`specs/always-present-companion/`)의 ReEngagementService가 이 게이트를 구현. 선제 인프라는 신규가 아니라 기존 선제 파이프라인(§10) 재사용. 범위(이어가기·open-loop·교차기기·시간인지)는 스펙 requirements 참조.
