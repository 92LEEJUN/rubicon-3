# ADR-0023: FE 상태관리 = React Query(서버) + Zustand(UI) + reducer

- **상태**: 채택(우선안)
- **관련**: `docs/frontend-architecture.md` §2·§11

## 배경
전역 채팅 패널 상태가 화면 이동에도 유지(R9), 스트리밍 부분 메시지 누적, 이력(R12). 서버 상태와 UI 상태를 어떻게 다룰지.

## 후보안
| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A (선택)** | **서버상태=React Query 계열 + 전역 UI=Zustand 계열 + 이벤트성=reducer** | 스트리밍·캐싱·무효화 잘 풀림, 전역 UI 경량, **보일러플레이트 최소** | 라이브러리 2종 |
| B | **Redux Toolkit** 단일 | 미들웨어 풍부·대규모 | 보일러플레이트↑(소규모 과함) |
| C | **Context만** | 의존성 0 | 리렌더·확장 약함 |

## 결정
**A.** 서버 데이터(기기·주문·이력·`home_summary`)는 Query 캐시, 채팅 스트림·`FlowState`·연결 상태머신·장바구니는 **reducer**(이벤트→상태 환원), 전역 UI/세션(패널·브릿지·화면맥락)은 경량 store.

## 기각 이유
- B: Redux는 이 규모에 보일러플레이트가 과하다.
- C: Context만으론 리렌더·확장이 약하다.

## 결과/영향
우선안 수준 — 스파이크/프로토타입 후 최종 확정(§13). 훅은 계약에만 의존해 교체 안전.
