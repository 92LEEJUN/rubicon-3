# ADR-0020: Mock↔실 경계 = Port/Repository 인터페이스 + 의존성 주입

- **상태**: 채택
- **관련**: `docs/architecture.md` §1·§5, `docs/data-model.md` §1·§6

## 배경
MVP는 외부 연동 대부분이 Mock이고 후속에 실 기능으로 전환된다. 전환이 **도메인 로직을 건드리지 않아야** 한다.

## 후보안
| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A | 외부 호출을 도메인에서 **직접/하드코드** | 빠름 | 실 전환 시 도메인 광범위 수정·외부 표현 누수 |
| **B (선택)** | **Port(어댑터)·Repository 인터페이스 + DI** 로 Mock/Real 교체 | 도메인 불변·병렬 개발·테스트 용이 | 추상화 비용 |
| C | 런타임 조건 분기(`if mock`) | 단순 시작 | 분기 난립·테스트 어려움 |

## 결정
**B.** 어댑터 경계 = Mock↔실 교체 지점. 저장소도 Repository로 추상화(**인메모리/로컬 기본 → Postgres+Redis 옵셔널**). **계약(Port 시그니처·타입)은 고정**, "어떤 소스 + 필드 매핑·적재"는 Real 구현 시 확정. 외부 스키마는 **ACL**에서 도메인 타입으로 변환(누수 격리).

## 기각 이유
- A: 실 전환 시 도메인 수정 범위가 커지고 외부 표현이 도메인에 샌다.
- C: 분기가 코드 전반에 퍼져 유지·테스트가 어렵다.

## 결과/영향
인증 토큰 격리는 ADR-0021(TokenProvider), 확인 UX/처리 분리는 ADR-0033, 데이터 계층 분리는 ADR-0035로 구체화.
