⚙️ Backend 도메인 (FastAPI)

BE 도메인 완성 가이드

도메인 로직 + 오케스트레이션 + 어댑터. 외부=Port, 내부=Repository. 이 문서 하나로 타입·인터페이스·결정이 완결된다.

책임엔티티PortRepository예외Mock↔실외부 데이터오케스트레이션결정스파이크레이아웃

01책임 / 경계

✅ 한다

  • 오케스트레이터(의도분류·흐름·tool·스트리밍)
  • 도메인 서비스(기기·CS·카탈로그·주문·개인화·알림)
  • Port/Repository 구현 + Mock↔실 어댑터(ACL)
  • RAG·이상 판정·부품 매칭
  • 되돌릴 수 없는 행동 게이트(R17)·폴백(R13)

🚫 안 한다

  • 화면 렌더 / 클라이언트 정형화(BFF)
  • WS 중계·인증 게이트(API/표현 계층)
  • (MVP) 실 결제·SSO·실 푸시 — Mock 경계 뒤

02도메인 엔티티 (핵심)

FastAPI/Pydantic 의사 타입. 식별자 Id=UUIDv4, 금액=정수(원, ≥0), 시간 UTC. 거래성 레코드 append-only.

User      { id, display_name, linked_device_ids[], preferences:UserPreferences, addresses[] }
Device    { id, type, model, status, consumables[], metrics }   # status=ST Health+operating
Consumable{ name, life_remaining 0~1, threshold 0~1 }
Anomaly   { id, device_id, type(error_code|consumable|abnormal_metric), severity(info
    
핵심 불변식


Order      DRAFT→CONFIRMED|FAILED, CONFIRMED→CANCELLED→REFUNDED. CONFIRMED=confirmed_at 필수(R17)
Solution   steps≥1, order 1부터 연속. sources 비면 escalation 권장
SolutionStep safety=danger | pro_required → 셀프 대신 기사 우선(R23)
Message    어시스턴트 본문=sections(단발 1, 복합 N). 미처리=handled:false(R7-3)
Quote      조회 본인 한정. active만 주문 전환(→converted), 만료 시 expired
Engagement append-only. Consent.scopes에 engagement 있을 때만(R19)
Notification opted_in=False면 전달 안 함

    

    
동의 scope (R19)


device_data(ST 기기) · personalization(이력 추천) · engagement(확인 정보 R29) · analytics(분석 R28)
※ 선제 알림 수신은 scope가 아니라 Notification.opted_in (R20)

03Port 인터페이스 (외부 = Mock↔실 경계)

AuthPort        current_user() / linked_devices(user_id)            # R15 Mock
DevicePort      list_devices() / get_status() / detect_anomalies()  # SmartThings
CSKnowledgePort find_solutions(query|Anomaly) -> [Solution]         # CS (빈 결과 가능)
CatalogPort     match_parts(device_id, spec) / get_product(s)(...)  # 제품 by-id·매칭(브라우즈 없음)
OrderPort       add_to_cart() / checkout() / cancel()               # O2O Mock
StorePort       find_stores(geo,type) / check_stock(store,part)     # O2O 후속
QuotePort       get_quote(ref) -> Quote                             # reverse O2O 후속
WarrantyPort    get_warranty(device_id) -> Warranty                 # R22
TrustPort       evaluate(answer, sources) -> (ok, score)            # R16
ActionGatePort  requires_confirmation(cta) -> bool                  # R17
HandoffPort     handoff() / list_slots(visit_type) / book_slot(...) # R18
AlertPort       deliver(notification)                               # R20 (opted_in=False면 no-op)
ConsentPort     get_consent() / revoke() / delete_data()            # R19 (cascade)
AnalyticsPort   track(event) / track_batch(events)                  # R28 (비차단·동의 없으면 no-op)
TokenProvider   access_token() -> str                               # 인증 교체 지점(PAT→OAuth→Enterprise)

각 Port는 Mock*(MVP)/Real*(후속), 의존성 주입 교체. 타임아웃·재시도, 실패는 PortError로.

04Repository (내부 데이터)

ConversationRepository  get / save(version 충돌=ConflictError) / list_by_user(limit,cursor)->Page
SessionRepository       load / store(state, ttl_sec)                # 세션 맥락(R6·R7), Redis 후보
OrderRepository         get / save
EngagementRepository    record / has_seen / dismissed / interests   # 유저 확인 정보(R29) — 내부=Repository
DeviceEvent  { device_id, capability, attribute, value, state_change, at }  # 폴링/구독 공통 정규화
내부=Repository, 외부=Port. 오케스트레이터→도메인은 인프로세스 함수. "전부 API가 아니다".

07외부 데이터 3종 (ACL 매핑)

SmartThings (DevicePort) — 실시간 이벤트

  • Health: ONLINE/UNHEALTHY/OFFLINE → Device.status. capabilities(attributes+commands).
  • filterStatus→Consumable/Anomaly, washer/dishwasherOperatingState→상태·metrics, custom.*(소모품·오류).
  • ⚠️ 기기 오류코드(4C/5C) API 노출 불확실(스파이크 확인). custom.disabledCapabilities 맹신 금지.
  • 인증 3계층 데이터/이벤트 공통, 토큰만 교체(TokenProvider). 이벤트 구독: Sink+Subscription, 배치 페이로드, HTTP Signature(rsa-sha256·digest·date<5m·공개키 동적 fetch).

Samsung CS (CSKnowledgePort) — 정적·구조적(배치 인제스천)

CS 콘텐츠우리 타입
오류코드+설명Anomaly(ERROR_CODE)/Solution.anomaly_id
원인+번호 단계SolutionStep.order/instruction
이미지/영상 · 서비스연결 · 부품 · 출처media · escalation_needed · required_parts · Source

검색=하이브리드: 오류코드 정확 매칭(키) + 자유 증상 벡터 유사도. 코드 매칭 우선.

제품정보 (CatalogPort) — demand-driven

나열/브라우즈 없음. 부품 매칭(R4)·추천(R8) 결과로만 카드/챗 노출. by-id·매칭만.

08오케스트레이션

파이프라인

수신 → ① 의도 분류·분해(하이브리드: 구조화 출력+규칙 가드레일)
     → ② 흐름 반영(FlowState) → ③ tool 선택·실행 → ④ 근거 보강(RAG)
     → ⑤ Template/Section 생성 → ⑥ 스트리밍(section 청크)

tool 레이어 — 구현은 API/DB/compute

tool구현 백엔드
get_device_statusPort(API) SmartThings
search_solutionsDB/검색 + RAG
match_parts / get_recommendationsDB 카탈로그·이력
get_historyDB(Repository)
create_orderPort O2O + ActionGate(R17)

tool 호출 메커니즘: LLM이 호출 요청→실행→결과 회신 반복(수동 루프). 프롬프트=system(정책)→tools→messages, 프롬프트 캐싱·추론 깊이 조절. 복합(R7)=의도별 섹션 묶음.
